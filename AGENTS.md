# Git workflow

- Use `<type>/<short-description>` for new branches, with a lowercase, hyphenated description.
- Choose a conventional type that matches the work: `feature`, `fix`, `docs`, `refactor`, `test`, or `chore`.
- Do not use `codex/` or other tool/agent names as branch prefixes.
- Follow an exact branch name when the user explicitly requests one.
- Keep portfolio development on topic branches and test locally; leave `main` unchanged until the user requests integration.
